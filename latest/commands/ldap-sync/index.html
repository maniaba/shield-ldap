    Synchronize Users

    Use shield:ldap-sync to provision eligible directory accounts and update mapped profiles on linked Shield users. The search uses LDAP paged results and combines loginFilter and eligibilityFilter across the configured userBaseDn values, or baseDn when userBaseDn is omitted.

    php spark shield:ldap-sync corporate
php spark shield:ldap-sync corporate --apply
    Connection option Effect
    provisionUsers Set to true to create Shield accounts for eligible directory entries with no existing link. New users receive Shield’s configured default group.
    updateProfile Set to true to apply mappings to existing linked accounts. Mappings also apply when creating accounts.
    profileAttributes Maps writable Shield fields to LDAP attributes. Map username when provisioning users.

    Synchronization matches existing links by immutable directory identifier and skips reserved local accounts. If an existing Shield username conflicts with a new directory account, verify both accounts and create the link first. Link Existing Users

    The native transport requires the directory to honor the critical LDAP paged results control. The command requests 100 entries per page and reports scan_limit_exceeded if it needs more than 10,000 pages across the configured bases. An incomplete scan stops before the command writes any users.

    The preview shows the changes planned against the current Shield data. Apply checks that data again before writing each user, so a later run can report different results. The command reports would_create and would_update in a preview and created and updated when applying changes. The summary includes unchanged and skipped accounts and conflicts. Conflicts cause a nonzero exit status.

    Each user's changes are committed in a separate transaction. If a run is interrupted, rerun the command from the beginning. Existing links identify users already processed. Deleted or disabled directory accounts keep their current local status. Review and update their Shield access through your application’s offboarding process.

    The command stages mapped profile values in memory up to PHP’s php://temp threshold of 2 MiB. Larger scans can spill into PHP’s system temporary directory. Use a restricted temporary directory on the host when processing sensitive profile attributes.

    Synchronize Only Groups

    Use --groups-only to reconcile mapped LDAP groups for existing Shield users linked to one connection. Run the preview, then use --apply to write the changes.

    php spark shield:ldap-sync corporate --groups-only
php spark shield:ldap-sync corporate --groups-only --apply

    This mode changes only LDAP group grants for eligible linked users. It preserves manual assignments and grants still backed by another connection. Provisioning and profile updates belong to the regular synchronization mode. Group-only synchronization skips reserved local accounts and users outside the eligible directory search results, including missing directory accounts. A failed or incomplete directory scan stops the run before any group changes are written.

    The native transport uses the configured service account over verified TLS. It checks direct membership against each mapped group DN and requests only the immutable ID from user entries. Apply the Shield LDAP grant table migration before running this mode. Use an explicit empty groupMappings array to withdraw this connection's grants for the eligible linked users returned by the scan.

    Run Every Five Minutes with CodeIgniter Tasks

    Install CodeIgniter Tasks and publish its configuration. See the CodeIgniter Tasks setup guide for the runner and Settings configuration.

    composer require codeigniter4/tasks
php spark tasks:publish

    Add this task to init() in app/Config/Tasks.php.

    $schedule->command('shield:ldap-sync corporate --groups-only --apply')
    ->everyFiveMinutes()
    ->singleInstance();

    Set up the Tasks runner in cron to dispatch scheduled tasks every minute. The LDAP task itself runs every five minutes.

    * * * * * cd /srv/myapp && /usr/bin/php spark tasks:run >> writable/logs/tasks-cron.log 2>&1

    Run Directly from Cron

    Add this entry to the crontab for the application's service account. Adjust the application and PHP paths.

    */5 * * * * cd /srv/myapp && /usr/bin/php spark shield:ldap-sync corporate --groups-only --apply >> writable/logs/ldap-group-sync.log 2>&1

    Use one scheduler per connection. When a run can take longer than the interval, use a lock such as flock on systems that provide it.

    Move Sign-In Updates to Scheduled Commands

    Set these options for the LDAP connection in app/Config/AuthLDAP.php to apply group and existing-user profile updates through Spark only.

    'syncGroupsOnLogin'  => false,
'syncProfileOnLogin' => false,
'updateProfile'      => true,

    Each sign-in still verifies credentials and LDAP eligibility. An application that enables sign-in provisioning continues to use mapped fields to create new Shield accounts. Mapped group changes take effect on the next successful group-only run. Keep profileAttributes and groupMappings configured for their respective commands.

    For CodeIgniter Tasks, add the two tasks to init() and configure the Tasks runner.

    $schedule->command('shield:ldap-sync corporate --apply')
    ->everyFiveMinutes()
    ->singleInstance();
$schedule->command('shield:ldap-sync corporate --groups-only --apply')
    ->everyFiveMinutes()
    ->singleInstance();

    For standard cron, run the profile command first. This lets group synchronization find users provisioned by the same run.

    */5 * * * * cd /srv/myapp && { /usr/bin/php spark shield:ldap-sync corporate --apply && /usr/bin/php spark shield:ldap-sync corporate --groups-only --apply; } >> writable/logs/ldap-sync.log 2>&1
