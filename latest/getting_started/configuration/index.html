    Configuration

    Create app/Config/AuthLDAP.php by extending the package's AuthLDAP class. Use the $connections property for directory settings and standard CodeIgniter environment overrides for deployment-specific values. LDAP sign-in is disabled by default. Enable it after configuring your directory and web login.

    Prepare the Directory and PHP Runtime

    1. Create a read-only service account that can search within the configured user base and read login attributes, immutable IDs, and attributes used by filters or profile mappings.

    2. Configure trust for the directory's CA in the OpenLDAP client settings used by PHP. You can use the following settings in the client configuration file, commonly /etc/ldap/ldap.conf.

      TLS_CACERT /etc/ssl/certs/corporate-ldap-ca.pem
TLS_REQCERT demand
TLS_REQSAN demand

    3. Confirm that the certificates presented by all endpoints are valid for the configured hostnames and chain to a trusted CA. Mount the CA bundle in the web runtime and restart PHP workers after updating their trust settings. A service manager can supply the CA path through the LDAPTLS_CACERT process environment variable. See the OpenLDAP TLS reference.

    Use ldaps for listeners that negotiate TLS as soon as they accept a connection (normally port 636). Use starttls for listeners that accept the LDAP StartTLS operation before bind (normally port 389). The native transport verifies certificates by default and rejects referrals. Verified connections use the OpenLDAP client trust policy for the PHP process.

    Local TLS Testing

    For controlled local testing with StartTLS, declare verifyCertificate in your connection settings in app/Config/AuthLDAP.php. For a connection named default, add these entries to $connections['default'].

    'encryption'        => 'starttls',
'verifyCertificate' => true,

    Override the option in the testing environment's .env.

    authldap.connections.default.verifyCertificate = false

    Warning

    Setting this option to false skips certificate chain and hostname checks. StartTLS is still required, but the client cannot verify the server's identity. Keep certificate verification enabled in production.

    The native transport supports this override for StartTLS starting with PHP 8.3.22 in the 8.3 series and PHP 8.4.8 in the 8.4 series. PHP 8.5 and later also support it. LDAPS and earlier PHP versions reject the override.

    Active Directory

    The following configuration searches two domain controllers in order. Users can sign in with sAMAccountName or userPrincipalName. The login filter excludes disabled accounts and objectGUID provides the immutable identity.

    <?php

declare(strict_types=1);

namespace Config;

use Maniaba\ShieldLDAP\Config\AuthLDAP as ShieldAuthLDAP;

class AuthLDAP extends ShieldAuthLDAP
{
    public string $defaultConnection = 'corporate';

    public array $connections = [
        'corporate' => [
            'hosts'               => ['dc01.example.com', 'dc02.example.com'],
            'baseDn'              => 'DC=example,DC=com',
            'bindDn'              => 'CN=shield-reader,OU=Service Accounts,DC=example,DC=com',
            'bindPassword'        => '',
            'encryption'          => 'ldaps',
            'port'                => 636,
            'userBaseDn'          => 'OU=Users,DC=example,DC=com',
            'loginFilter'         => '(&(objectCategory=person)(objectClass=user)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))',
            'loginAttributes'     => ['sAMAccountName', 'userPrincipalName'],
            'externalIdAttribute' => 'objectGUID',
            'profileAttributes'   => ['username' => 'sAMAccountName'],
            'provisionUsers'      => true,
        ],
    ];
}

    Supply the password and enable LDAP through .env.

    authldap.enabled = true
authldap.connections.corporate.bindPassword = 'replace-with-service-account-password'

    OpenLDAP

    For an OpenLDAP server with StartTLS, use the following app/Config/AuthLDAP.php. This example looks up users by uid and links their Shield accounts by entryUUID. Allow the service account to read that operational attribute.

    <?php

declare(strict_types=1);

namespace Config;

use Maniaba\ShieldLDAP\Config\AuthLDAP as ShieldAuthLDAP;

class AuthLDAP extends ShieldAuthLDAP
{
    public string $defaultConnection = 'openldap';

    public array $connections = [
        'openldap' => [
            'hosts'               => ['ldap.example.org'],
            'baseDn'              => 'dc=example,dc=org',
            'bindDn'              => 'cn=shield-reader,ou=services,dc=example,dc=org',
            'bindPassword'        => '',
            'encryption'          => 'starttls',
            'port'                => 389,
            'userBaseDn'          => 'ou=people,dc=example,dc=org',
            'loginFilter'         => '(objectClass=inetOrgPerson)',
            'loginAttributes'     => ['uid'],
            'externalIdAttribute' => 'entryUUID',
            'profileAttributes'   => ['username' => 'uid'],
            'provisionUsers'      => true,
        ],
    ];
}

    Supply the password under the connection ID openldap.

    authldap.enabled = true
authldap.connections.openldap.bindPassword = 'replace-with-service-account-password'

    For another LDAPv3 server, choose the login attributes, filters, and immutable identifier according to its schema. The identifier must be unique, readable, and stable across account renames and moves. See Login Eligibility and the configuration reference.

    Multiple Search Bases

    Set userBaseDn to a list of 1 to 10 distinguished names to configure the user search bases. For example, add these settings to the corporate connection to search two sibling organizational units in Active Directory.

    'baseDn'     => 'DC=example,DC=com',
'userBaseDn' => [
    'OU=Employees,DC=example,DC=com',
    'OU=Contractors,DC=example,DC=com',
],

    Use a string userBaseDn for a single user search base. If you omit it or set it to null, user searches use the root DN in baseDn. The service account needs permission to search each selected base. The native transport checks for a single match across the selected bases before it verifies the password. See the configuration reference.

    Map LDAP Groups to Shield Groups

    Run the migrations after installing Shield to create the table that records LDAP group assignments. To use a custom table name, add the following entry to the existing $tables array in app/Config/Auth.php before running the migration.

    'ldap_group_grants' => 'auth_ldap_group_grants',

    If Shield's config omits this key, Shield LDAP reads it from $tables in app/Config/AuthLDAP.php. The default is shield_ldap_group_grants.

    php spark migrate --all

    If the grants table already exists, rename it in the database when updating this setting so its recorded assignments carry over.

    Set groupMappings on each connection that should manage Shield groups. Use a key from Config\AuthGroups::$groups on the left and the full DN of an LDAP group entry on the right.

    'groupMappings' => [
    'user'      => 'CN=Users Group,OU=Groups,DC=example,DC=com',
    'developer' => 'CN=Developers,OU=Groups,DC=example,DC=com',
],

    For OpenLDAP, a group DN might be cn=shield-users,ou=groups,dc=example,dc=org. An organizational unit such as OU=Users,DC=example,DC=com is a container. Use the DN of the group entry that lists its members.

    The service account needs permission to search each mapped group by its membership attribute. The native directory checks direct member membership for Active Directory group and OpenLDAP groupOfNames entries, and direct uniqueMember membership for groupOfUniqueNames. Active Directory primary groups and membership inherited through nested groups are outside this lookup. See Group assignments for how assignments are stored.

    Set groupMappings to an empty array to revoke this connection's previous grants when group synchronization runs. Omitting the option or setting it to null disables group management for that connection. See Move Sign-In Updates to Scheduled Commands to control when group and profile updates run.

    Environment Overrides

    Keep .env outside version control. When a deployment environment requires underscores in variable names, use keys such as authldap_connections_corporate_bindPassword. The normal CodeIgniter config initialization applies these overrides. Declare the connection ID and each option before setting its environment override. The same rule applies to list entries, such as authldap.connections.corporate.hosts.0.

    Warning

    Direct reads of $connections, configuration exports, and CodeIgniter's configuration cache can expose the bind password. Use an application-owned connection provider if the password must stay outside the configuration cache.

    Multiple Directories

    List replicas of one directory in a single connection's hosts, in preference order. Give independent directories separate connection IDs. If users enter UPNs from different directories, map each lower-case suffix to a connection ID.

    public array $loginDomains = [
    'example.com'          => 'corporate',
    'research.example.org' => 'research',
];

    Declare corporate and research under $connections before using this example. The default connection handles unqualified identifiers and unmapped suffixes. The selected connection looks up the entire submitted identifier, including any suffix. Keep connection IDs stable because they identify the scope of the link between a directory account and a Shield user.
